Backend notes

  • Data model: user profiles, plants, care schedules/reminders, social graph (friends/requests), and activity/feed events; persisted via Firestore collections (per-user scoped) with local caching/persistence where applicable.
  • API surface: Firebase Auth for identity, Firestore for CRUD operations and real-time updates, FCM for notifications, and external REST integrations via Retrofit/OkHttp (e.g., Plant.id).
  • Failure modes: offline-first behavior (cached reads), retries/backoff for network calls, idempotent writes where possible, and conflict avoidance via server timestamps and document-level updates.
  • Testing: unit tests for repository/data-layer logic; UI tests where relevant (expand coverage as time allows).
  • Deployed / run: runs as an Android app with Firebase as the backend platform; local dev uses Firebase project configuration and can be exercised via seeded Firestore data and emulator-backed flows when configured.
